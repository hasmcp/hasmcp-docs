# Creating a Server Variable

A variable is an `ENV` value or an encrypted `SECRET` that HasMCP injects into provider tool headers, for example `Authorization: Bearer ${API_GITHUB_COM_PRIVATE_TOKEN}`.

A variable applies either to **all servers** or to **a single MCP server**. When a server needs a variable, it uses its own value first and falls back to the value for all servers. See [Per-Server Variables & Credentials](/features/per-server-variables).

## Using HasMCP UI

### From the server (recommended)

1. Open the MCP server and go to the **Configuration** tab.
2. The **Variables** section lists the variables the server's enabled tools need. Click a missing one to fill it in.
3. Enter the **Value** and pick the type (`ENV` for plain text, `SECRET` for encrypted storage).
4. Leave **This server only** on to scope the variable to this server, or turn it off to use it for all servers.
5. Click **Add Variable**.

To give one server a different value for a variable that's shared by all servers, click **Override** next to it.

### From the Variables page

![Variables Interface](../images/kb/variables_page_check.png)

1. Open **Variables** from the sidebar.
2. Click **Create Variable**.
3. Enter the name your provider expects (e.g., `API_MOLTBOOK_COM_BEARERAUTH`), the **Value** and the **Type**.
4. Click **Save**.

Variables created here apply to all servers. The **Scope** column shows which variables belong to a single server.

Servers that use the variable are refreshed right away.

## Using REST API

### The API Endpoint

**`POST /variables`**

```bash
curl -X POST https://app.hasmcp.com/api/v1/variables \
 -H "Authorization: Bearer YOUR_TOKEN" \
 -H "Content-Type: application/json" \
 -d '{
 "variable": {
 "name": "API_MYSYSTEM_COM_API_KEY",
 "value": "sk-123abc456def",
 "type": "SECRET",
 "serverID": "OPTIONAL_MCP_SERVER_ID"
 }
 }'
```

Leave out `serverID` to create the variable for all servers. HasMCP responds with `201 Created` and the `Variable`. A `SECRET` value is masked in the response.
