---
title: "Self Hosted"
description: "Run HasMCP Pro or HasMCP Enterprise on your own infrastructure with Docker and a license key."
---

HasMCP Pro and HasMCP Enterprise run on your own machines as a single Docker container. HasMCP ships as a single binary with the web app and the default configuration built in, and the `hasmcp/hasmcp` image holds only that binary. The same image serves both editions; your **license key** decides which one you get. Licenses are per machine, regardless of the number of cores.

<Note>
To get a license key, or to move from the Community Edition (`hasmcp-ce`) to Pro or Enterprise, email [license@hasmcp.com](mailto:license@hasmcp.com).
</Note>

## Prerequisites

- **Docker** on a Linux machine (`amd64` or `arm64`).
- **A license key** (`license.key`) for HasMCP Pro or Enterprise.
- **For production:** a domain name pointing to the machine, with ports `80` and `443` open, so HasMCP can get a TLS certificate from Let's Encrypt.
- **Optional:** a PostgreSQL database. HasMCP can also run on SQLite.

## 1. Get the Setup Kit

The [hasmcp-pro-local-setup](https://github.com/hasmcp/hasmcp-pro-local-setup) repository has a `Makefile` and an example `.env` to run the container with.

```bash
git clone https://github.com/hasmcp/hasmcp-pro-local-setup.git hasmcp
cd hasmcp
mkdir -p _certs _license _storage
chmod 0777 _certs _storage
```

HasMCP reads only your own files from disk. The container mounts these folders:

| Folder | Contents |
| :--- | :--- |
| `_license/` | Your `license.key`. Optional once the key is [set another way](#2-install-the-license-key). |
| `_storage/` | Application data: the SQLite database (if used) and the settings saved on the [setup page](#4-finish-on-the-setup-page) |
| `_certs/` | The Let's Encrypt certificate cache |

<Warning>
Back up `_storage/` and your `.env`. Without `HASMCP_APP_ENCRYPTION_KEY`, the stored secrets and saved settings can't be decrypted.
</Warning>

## 2. Install the License Key

```bash
cp /path/to/your/license.key ./_license/license.key
```

HasMCP reads `/_license/license.key` at startup and **won't start without a valid key**. Instead of the file, you can set the key with `HASMCP_APP_LICENSE_KEY` in `.env`, or enter it later in the **License** section of the [setup page](#5-finish-on-the-setup-page). Both override the file. Each license is issued for an environment (usually `production`). Set `ENV` in `.env` to the same value, or HasMCP stops with `invalid license environment`.

## 3. Configure the Environment

```bash
cp .env.example .env
```

Edit `.env`. These values matter most for a first start:

| Variable | Description |
| :--- | :--- |
| `ENV` | `production` (must match your license) |
| `HASMCP_APP_API_ACCESS_TOKEN` | The **root access token**: you sign in to the UI, the API and the setup page with it. Use a long random value. |
| `HASMCP_APP_ENCRYPTION_KEY` | 32 bytes as 64 hex characters. Encrypts secrets, tokens and saved settings. Never change or lose it. |
| `HASMCP_APP_HASH_SALT` | Salt for the values HasMCP stores hashed |
| `HASMCP_APP_MCP_JWT_SECRET`, `HASMCP_APP_OAUTH2_PROVIDER_JWT_SECRET` | Signing secrets for MCP sessions and OAuth2 state |
| `HASMCP_APP_ACCOUNT_SERVICE_ENABLED` | `false` for self-hosting: you sign in with the root access token |
| `HASMCP_APP_SERVER_DOMAIN_NAME` | The domain HasMCP is served on, e.g. `mcp.example.com` |
| `HASMCP_APP_MCP_BASE_URL` | The public URL MCP clients connect to, e.g. `https://mcp.example.com` |
| `HASMCP_APP_OAUTH2_PROVIDER_HTTP_SCHEME` | `https` in production. OAuth2 redirects go to `<scheme>://<domain>/oauth2/callback`. |
| `HASMCP_APP_SERVER_SSL_ENABLED`, `HASMCP_APP_SERVER_LETSENCRYPT_EMAIL` | Set to `true` with your email to get a certificate from Let's Encrypt automatically |
| `PORT` | The HTTP port inside the container (`80`) |

Generate the keys and secrets with:

```bash
hexdump -vn32 -e'4/4 "%08X" 1 "\n"' /dev/urandom   # 32 bytes (64 hex chars)
hexdump -vn16 -e'4/4 "%08X" 1 "\n"' /dev/urandom   # 16 bytes (32 hex chars)
```

<Warning>
Don't keep the example values from `.env.example`. If the root access token is left at its default, HasMCP logs a warning and the setup page flags it as insecure.
</Warning>

### Database

With `ENV=production`, HasMCP uses PostgreSQL by default:

```bash
HASMCP_APP_POSTGRES_ENABLED=true
POSTGRES_HOST=db.internal
POSTGRES_PORT=5432
POSTGRES_USER=hasmcp_app
POSTGRES_PASSWORD=<password>
POSTGRES_DBNAME=hasmcp_app
POSTGRES_TIMEZONE=UTC
```

For a single machine, SQLite is simpler. The database is stored in `_storage/hasmcp.sqlite3`:

```bash
HASMCP_APP_POSTGRES_ENABLED=false
HASMCP_APP_SQLITE_ENABLED=true
```

### Optional Settings

- **S3-compatible storage** (`HASMCP_APP_S3_*`) for uploaded provider icons.
- **Git connections** (`HASMCP_APP_GIT_OAUTH2_GITHUB_*`, `HASMCP_APP_GIT_OAUTH2_GITLAB_*`) to push server configurations to GitHub or GitLab. See [Git Connections](/features/git-connections).
- **Per-API CORS, logging and rate limits** (`HASMCP_APP_{API,HUB,MCP,OAUTH2,CONFIGURATION_API}_*`).

You can also leave these out and set them later on the setup page.

## 4. Start HasMCP

```bash
docker run -d --name hasmcp --restart always \
  --env-file .env \
  -p 80:80 -p 443:443 \
  -v ./_certs:/_certs \
  -v ./_license:/_license \
  -v ./_storage:/_storage \
  hasmcp/hasmcp:latest
```

Or use the kit's `Makefile`:

| Command | Description |
| :--- | :--- |
| `make setup` | Creates the `_certs`, `_license` and `_storage` folders |
| `make restart` | Removes the container and runs it again, e.g. after changing `.env` |
| `make update` | Pulls the latest image and recreates the container |
| `make up` / `make down` | Starts / stops the existing container |
| `make logs` | Follows the container logs |
| `make stats` | Shows resource usage |

Open `https://<your domain>` (or `http://localhost` for a local test) and sign in with the **root access token**.

## 5. Finish on the Setup Page

Open `/setup` and sign in with the root access token. The setup page can change every setting the `.env` file sets, so you can manage the server without editing files:

| Section | Settings |
| :--- | :--- |
| **Domain** | Domain name, MCP base URL, MCP proxy URL, OAuth2 callback scheme |
| **Server** | Port, request body size limit, trusted proxies, ID node |
| **TLS** | Let's Encrypt on/off, TLS port, email |
| **Database** | SQLite or PostgreSQL, and the connection |
| **Storage** | S3 endpoint, region, bucket, keys and public bucket URL |
| **Accounts** | Account service and its URLs |
| **Git** | GitHub App and GitLab OAuth app |
| **APIs** | CORS hostnames, logging, rate limits and authentication for the API, Hub, MCP, OAuth2 and Configuration APIs |
| **Tracking** | A tracker script (such as an analytics `<script>`) added to the end of the `<head>` of every page of the web app |
| **Secrets** | Hash salt and the JWT secrets |
| **License** | A new license key. It's checked before saving and must be for the server's `ENV`, so a wrong key can't stop the next start. |

How saved settings behave:

- They are encrypted with `HASMCP_APP_ENCRYPTION_KEY` and saved to `_storage/settings.json` (or to `HASMCP_APP_SETTINGS_FILE`).
- They **override** the `.env` file and the built-in configuration. After you save a setting, changing it in `.env` has no effect.
- They apply on the **next restart** (`make restart`).
- Secrets and the license key are never shown again. Leave one blank to keep its current value. Changing a JWT secret or the hash salt can sign users and MCP clients out, or make stored hashes stop matching. Change them only when you need to.

Only `HASMCP_APP_API_ACCESS_TOKEN`, `HASMCP_APP_ENCRYPTION_KEY` and `ENV` must stay in `.env`.

## Updating

```bash
make update
```

`latest` follows the newest release. To pin a version, use a `sha-<commit>` tag from [Docker Hub](https://hub.docker.com/r/hasmcp/hasmcp/tags):

```bash
make update HASMCP_VERSION=sha-b0c10f1
```

Database migrations run automatically on startup. Back up `_storage/` (and your PostgreSQL database) before updating.

## Troubleshooting

| Symptom | Fix |
| :--- | :--- |
| The container exits right after starting | Run `make logs`. Lines starting with `[license]` mean the key is missing, invalid, or for a different `ENV`. A key set on the setup page or with `HASMCP_APP_LICENSE_KEY` takes precedence over `license.key`. |
| Can't sign in to the UI | Use the value of `HASMCP_APP_API_ACCESS_TOKEN`, and check that `HASMCP_APP_ACCOUNT_SERVICE_ENABLED=false` |
| No TLS certificate | The domain must resolve to the machine and port `80` must be reachable for the Let's Encrypt challenge. Let's Encrypt needs a public domain; it can't issue a certificate for an IP address or `localhost`. |
| OAuth sign-in fails with a redirect error | Register `https://<your domain>/oauth2/callback` with the OAuth app, and set `HASMCP_APP_OAUTH2_PROVIDER_HTTP_SCHEME=https` |
| A changed `.env` value has no effect | The setting was saved on the setup page, which takes precedence. Change it there and restart. |
